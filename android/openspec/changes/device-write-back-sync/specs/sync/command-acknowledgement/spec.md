## Purpose

让云端能够知道一条经 MQTT 下发的写命令是否已经在设备上真正生效，供云端的待同步队列（`docs/小程序与PC端集成设计.md` §5.2）匹配状态，而不是发出去就当作成功。

## ADDED Requirements

### Requirement: 每条写命令处理后都发布确认应答
设备处理完一条经 MQTT 下发的配置更新或记录修正命令后，SHALL 发布一条带有该命令原始标识与处理结果（成功/失败）的确认应答消息。

#### Scenario: 命令成功应用
- **WHEN** 设备成功应用一条配置更新命令
- **THEN** 设备发布一条确认应答，其中包含与该命令相同的标识，处理结果为成功，且携带应用后的实际生效值

#### Scenario: 命令应用失败
- **WHEN** 设备处理一条记录修正命令时发现目标记录不存在（见 `record-correction` 能力）
- **THEN** 设备发布一条确认应答，其中包含与该命令相同的标识，处理结果为失败

### Requirement: 确认应答与查询类应答语义不混淆
确认应答（表示"某条写命令的处理结果"）SHALL 与现有的查询类应答（表示"分页查询结果"）在结构上可区分，不得复用完全相同的消息结构导致云端无法区分两者。

#### Scenario: 云端同时收到查询应答和确认应答
- **WHEN** 云端在短时间内先后收到一条分页查询应答和一条命令确认应答
- **THEN** 云端能通过消息结构或标识字段明确区分这是两种不同语义的消息，不会把确认应答误当作查询结果解析
