# 远程配置下发：字段清单（RPC）

**状态**：Android 侧已实现（2026-10-08，`SetTankSettingsHandler`/`SetDeviceSettingsHandler`），JVM 单测通过。云端已按本清单实现并对齐（cloud#70/#71，契约 `cloud/docs/tank-settings-contract.md`；提交保护 `cloud/docs/config-command-contract.md`，#3）。
**真机**：2026-11-08 生产 ZCT000001 单字段 `config.setTankSettings`（`alarmHighLevelMm`）已验证 ACK→`cmdResult`→属性回显→重启持久化（`cloud/docs/tank-settings-device-verification.md`）；其余字段、整机设置、失败与离线路径仍未真机验证（#9）。
**依据代码**：`main`（PR #38 于 2026-11-02 合并）。
**相关**：设备上报的同名字段见 `docs/ThingsBoard接入现状与待办.md` §3.5（客户端属性）。下发与上报**用同一套字段名**，云端读写一致。

## 1. 总规则

| 项 | 规则 |
|---|---|
| 通道 | ThingsBoard 服务端 RPC，沿用现有框架（`RpcDispatcher`）：`received`/`rejected` 走 ACK，执行结果走 `cmdResult` 遥测，带 `commandId` 去重和过期检查 |
| 部分更新 | 只改 args 里出现的字段，未出现的保持不变；没有任何可改字段时拒绝 |
| 原子性 | 任一字段校验不通过，整条命令拒绝（`INVALID_PARAMS`），不写入任何字段 |
| 未知字段 | 按协议 §2 忽略，列在 `cmdResult.detail.ignored` 里；云端据此发现拼错的字段名 |
| 不开放字段 | 拒绝（见 §2 不开放的字段）：云端发了是期望生效的，忽略会误以为改成功 |
| 写入 | 罐设置同步写库（一行，原子）、失败回 `failed`；整机设置所有字段**一次** `commit()`（`SharePrefUtil.saveIntsChecked`，#9），要么全写入要么都不改，失败回 `failed`「未修改任何字段」 |
| 生效 | 罐设置写入后刷新 `OilcanDataManager` 缓存（报警检测读缓存）；整机阈值写入后刷新 `Singleton` |
| 回执 | `cmdResult.detail`（线上字段名是 `detail`，不是 `data`）带实际修改和被忽略的字段，如 `{"tank":1,"updated":["alarmHighLevelMm"],"ignored":["foo"]}` |
| 属性回显 | 写入后客户端属性自动重发（防抖 2 秒），云端可读回确认 |

## 2. `config.setTankSettings`：修改单个罐的设置

示例：`{"tank": 1, "alarmHighLevelMm": 650, "density": 0.56}`

| 字段 | 本地字段 | 类型 | 单位 | 取值范围 | 说明 |
|---|---|---|---|---|---|
| `tank` | `pk_oilCanId` | int | — | 1～16，且该罐已启用 | 必填 |
| `alarmHighHighLevelMm` | `hheightOilAlarm` | int | mm | 0～罐高 | 0 = 不启用 |
| `alarmHighLevelMm` | `heightOilAlarm` | int | mm | 0～罐高 | 同上 |
| `alarmLowLevelMm` | `lowOilAlarm` | int | mm | 0～罐高 | 同上 |
| `alarmLowLowLevelMm` | `llowOilAlarm` | int | mm | 0～罐高 | 同上 |
| `alarmHighWaterMm` | `heightWaterAlarm` | int | mm | 0～罐高 | 同上 |
| `alarmHighTempC` | `highTempAlarm` | int | ℃ | −50～100 | 0 = 不启用（无法设"0 ℃ 报警"，与本地一致） |
| `levelCorrectionMm` | `oilCorrection` | number | mm | 不限（有限数字） | #28 |
| `waterCorrectionMm` | `waterCorrection` | number | mm | 不限（有限数字） | #28 |
| `tempCorrectionC` | `tempCorrection` | number | ℃ | 不限（有限数字） | #28 |
| `customOilName` `customOilNameEn` | 名称表 32–39 | string | - | 1–20 / 1–40 字符 | 只能和 32–39 的 `oilTypeIndex` 一起下发，同时生效（#27） |
| `density` | `density` | number | 待对齐 | 大于 0 且不超过 2 | 原样写入；设置页标 kg/m³，库里实际存 0.56 这类值 |
| `oilTypeIndex` | `oilType` | int | — | 0～39 | 0 = 未设置；1～31 内置介质；32～39 自定义介质（目前没有写入入口，名称恒为空） |
| `capacityL` | `maxVolume` | int | L | 0～1,000,000 | 只影响空容/可添油量计算 |

**液位阈值顺序**：只在本次下发包含液位阈值字段时校验（本地设置页不校验顺序，库里可能本就不合规，不能因此挡住改密度这类无关修改）。本次下发值与库里现值合并后校验；0 表示不启用、不参与比较；非 0 的值必须 低低 < 低 < 高 < 高高。

### 不开放的字段

| 字段 | 原因 |
|---|---|
| `alarmLowTempC` | 本地低温检测从未被调用（`AlarmDetection.tempLowDection` 标 `[不可达-2026-09-21]`），改了不生效 |
| `tankHeightMm` | 本地按"罐高 > 0"自动启用/停用罐，远程改会联动启停 |
| `probeAddress` | 改错即与探针断开通讯 |
| `tankShape` | 影响罐体图示与计算口径，安装阶段一次性设置 |
| `sensorLengthMm` | 由探针 42 应答读出，本地点"保存数据"时以探针值覆盖，远程改没有意义 |

## 3. `config.setDeviceSettings`：修改整机设置

示例：`{"outStockHeightThresholdMm": 20, "outStockTimeThresholdSec": 60}`

| 字段 | 本地 | 类型 | 单位 | 取值范围 |
|---|---|---|---|---|
| `inStockHeightThresholdMm` | `InHight` | int | mm | 1～10000 |
| `inStockTimeThresholdSec` | `InTime` | int | s | 1～86400 |
| `outStockHeightThresholdMm` | `OutHight` | int | mm | 1～10000 |
| `outStockTimeThresholdSec` | `OutTime` | int | s | 1～86400 |

下限为 1：本地基础设置页填 0 不保存（`SetBaseFragment` 的 `!= 0` 判断），远程保持一致。

## 4. 与旧方法的关系

`config.setAlarmThresholds`（`SetAlarmThresholdHandler`，args 用本地字段名 `hheightOilAlarm` 等）**保留不动**，兼容云端现有调用。差异：旧方法要求四级阈值严格递减、不能把某一级设为 0；新方法允许 0 = 不启用。建议云端后续改用 `config.setTankSettings`。

## 5. 上报侧配套

客户端属性新增 `tank{N}.oilTypeIndex`（油品序号）：现有 `tank{N}.oilType` 是名称，会随界面语言变化，云端读写应以序号为准。

## 6. 已知限制

| 级别 | 问题 | 结论 |
|---|---|---|
| 低 | 设置页开着时远程改了设置，现场再点"保存"会用页面内存里的旧值覆盖（`OilCanSetFragment` 整条写回） | 暂不修：需同时满足三个条件；修要改本地设置页保存逻辑 |
| 低 | 整机阈值由 RPC 线程写入 `Singleton` 普通 int 字段、主线程读，无可见性保证 | 暂不修：实际影响可忽略 |

另：设备**没有"现场手动模式"**这一状态，也不上报 `localControlMode`；协议里的 `LOCAL_MODE_LOCKED` 不会出现。若将来需要
现场/远程互锁，需另行定义产品行为与协议（#9）。
