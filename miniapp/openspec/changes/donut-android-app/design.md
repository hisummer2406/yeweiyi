## Context

- 原生微信小程序 + TypeScript，无打包器。`wx.*` 用到的只有 `request`、`connectSocket`、`scanCode`、`showActionSheet`、存储，以及仅登录用的 `wx.login` 和 `<button open-type="getPhoneNumber">`（`utils/auth.ts`、`pages/login/login.wxml`）。
- 登录页默认是"微信登录"标签，另有"账号密码登录"标签；`buildPasswordLogin` 把非大陆手机号的输入当作 `username` 发出。
- 中文散落在约 55 个 `.ts`/`.wxml`/`.json` 文件中（`.wxml` 约 177 行、`.ts` 约 232 行含中文），包括 `app.json` 的 tabBar 和导航栏标题、各页面 `.json` 标题、`utils/labels.ts`、`utils/loginFlow.ts` 的失败文案。没有任何多语言机制。
- `utils/ws.ts` 已有指数退避重连（2s→60s），但没有"回到前台／网络恢复时立即重连"，退避期间用户无法得知数据是否新鲜。
- `config/env.ts` 线上地址是 `http://8.154.38.176`（明文、IP）。另有一处未提交的本地改动（`DEBUG_MODE` 改为 `true`），属于用户本地状态，本变更不触碰它。

云端对照基线：yeweiyi-cloud main `af8525a`（含 #68、#62）。已读 `docs/account-phone-wechat-contract.md`：客户侧账号 `users.username` 由服务端设为等于 `phone`（`CHECK`），手机号必填、全局唯一、仅 11 位大陆号；`customer_user` 的密码必须为 NULL，创建时带密码返回 `400 password_not_allowed`；登录接口 `username` 路径只接受平台管理员、`phone` 路径只接受客户管理员。**这与"国外用户用管理员分配的用户名＋密码登录"直接冲突。**

Donut 官方文档核实（2026-10-19，只读了概述、登录、API 适配、打包几页，见 issue #12）：

- 可在微信开发者工具"构建 → 打包生成 APK"，需自备签名证书；每个开发者每自然周 50 次免费原生构建，仅小程序代码变更不占额度。

- `wx.login` 在 App 中不适用；官方身份服务无账号密码登录，但文档未说必须使用它。
- 免费版带水印；专业版目前只对已上架应用免费开放。

文档未说明、只能靠真机验证：没装微信的手机能否运行与登录；AppID 类型／企业认证要求；Android 内部分发与覆盖更新；`wx.getSystemInfo` 变化对本项目的影响。

补充核实（2026-10-19，任务 1.3，官方文档原文）：

- **条件编译**：WXML 用 `<!-- #if MP -->…<!-- #endif -->`，JS/TS 用 `// #if MP`…`// #endif`，WXSS 用 `/* #if MP */`；`MP` 是微信小程序，`ANDROID`/`IOS`/`OHOS` 是各 App 目标，`NATIVE` 指 Android 或 iOS。支持 `||`。JSON 不用 `#if`，改为平台键（如 `"mini-ios"`）覆盖基础配置，且 JSON 里不支持 `||`。**须先在开发者工具"详情 → 本地设置 → 启用条件编译"打开才生效。**
- **`project.miniapp.json`**：顶层 `miniVersion`、`name`、`version`、`versionCode`（整数，每次发布必须递增）、`i18nFilePath`；Android 块 `mini-android` 里 `useExtendedSdk` 有 `network`、`scanner` 等布尔开关，另有 `icons`、`splashscreen`、`privacy`、`privateDescriptions`（Android 权限说明）。**包名不在这个文件里**，在多端应用控制台设置：未绑定移动应用时用"自定义配置"填写，且不能是测试用的 `com.tencent.weauth`；包名与已安装包不一致会导致无法启动。
- **官方"多语言适配"只是构建期配置**：覆盖 App 名称、权限说明、隐私弹窗、启动页、网络错误页，用 `i18n/base.json`、`zh.json`、`en.json` 等文件。**文档没有运行时读取或切换语言的接口。** 因此 D3 的运行时词表不与官方方案冲突，两者互补：运行时词表管界面文案，官方方案只用来本地化 App 名称、权限说明与启动页。
- `wx.getSystemInfo` 在 App 中返回参数有变化（来自适配列表），`language` 字段在 App 中是否可用**未能查到**，须真机验证；不可用时默认语言回退英文。

核对云端登录类型（任务 1.4，云端检出 `af8525a`，`internal/api/auth.go`、`wechat.go`、`admin.go` 与 `docs/account-phone-wechat-contract.md` §3.1）：`types/api.d.ts` 的 `SessionUser`（`role`、`customerId`、`username`、`phone`、`disabled`）与 `LoginResponse` 与云端一致；`loginFlow.ts` 的 `BY_CODE` 覆盖云端登录相关的全部 `code`。云端目前没有"需要改密"标记或改密接口，所以客户端没有对应类型，等 cloud#77 落地后再同步。

## Goals / Non-Goals

**Goals:**
- 在没有微信的 Android 手机上，管理员和员工都能用用户名＋密码登录并完成核心只读流程（及管理员既有的控制入口）。
- 同一份代码继续服务原微信小程序，不破坏其行为。
- 界面支持中／英／西三种语言，并能低成本新增语言。
- 国外网络下，用户总能分辨"数据是新的／旧的／读取失败"。
- 尽早拿到可安装的验证包，把平台层面的未知数用真机结果而不是推测确认。

**Non-Goals:**
- 应用商店上架、iOS、系统级推送。
- 在 App 里提供微信登录、短信验证码、邮箱登录。
- 替云端定账号契约；改设备协议；重设计 UI；改用其他框架。
- 西班牙语专业术语校对（上线后再改）。

## Decisions

### D1 一份代码、两个目标，平台差异用条件编译隔离

App 与小程序共用同一代码库。只在"登录入口"这一处出现平台分叉：小程序保留微信登录；App 不渲染任何微信入口。条件编译的具体写法**以官方文档和开发者工具生成结果为准，不猜测**（任务里先核实）。

- 备选：为 App 另开仓库／分支。放弃：两份代码必然漂移，且 issue 明确要求保护原小程序。
- 备选：运行时判断"是否 App"。可作为条件编译不可用时的退路，但微信相关代码仍会被打进 App；先以条件编译为首选。

### D2 App 的登录只用现有的 `POST /api/login`，不用 Donut 官方身份服务

走自己云端的账号密码接口（`wx.request`），不接入 Donut 的短信／一键登录／Apple。理由：官方身份服务没有账号密码，且会在云端之外再引入一套身份，与"云端签发业务令牌、客户端不绕过权限"冲突。

客户端登录表单保持一个"账号"输入框（占位文案随语言），沿用 `buildPasswordLogin` 的判断，但**哪种账号标识被云端接受由云端决定**：客户侧用户名落地后，客户端把非手机号形态的输入作为 `username` 发出即可，预计改动很小。客户端不校验用户名格式，只校验非空（云端的 400 才是准）。

- **云端依赖（阻塞）**：客户侧账号需要独立用户名；管理员能为员工设置／重置密码；`customer_user` 允许密码登录。须另开 yeweiyi-cloud issue，由云端出契约后再接。契约落地前，App 只能用现有能力验证（管理员手机号＋密码，或平台管理员用户名）。
- 首次登录改密：是否强制、云端是否提供"首次登录需改密"标记、改密接口是什么，均属云端契约。本设计只规定客户端行为：云端若标记需改密，则登录后先进入改密；没有该标记前，不自行发明接口，只在设置页提供入口（若云端有改密接口）。列入 Open Questions。

### D3 多语言：词表 + `t()`，切换语言后整体重载

- 新增 `locales/zh.ts`、`en.ts`、`es.ts`，键为稳定的点分字符串，值为文案，支持 `{name}` 形式的占位符。`utils/i18n.ts` 提供 `t(key, params?)`、`currentLocale()`、`setLocale()`；纯函数，不依赖 `wx`，便于 Node 检查。
- 缺词条：当前语言 → 英文 → 键本身（开发期可见）。不显示空白。
- 页面取字：原生小程序的 WXML 不能直接调用 TS 函数，各页面在 `onLoad/onShow` 把本页用到的文案 `setData` 到 `text` 对象。切换语言后 `wx.reLaunch` 到首页，不做各页面的实时重渲染。
- 不能被词表覆盖的静态位置：`app.json` 的 tabBar 文字、各页面 `.json` 的导航栏标题。用 `wx.setTabBarItem`、`wx.setNavigationBarTitle` 在 `onShow` 设置。
- 默认语言：首次启动读系统语言，匹配到支持的语言就用，否则英文；用户手动选择后写入本机存储，优先于系统语言。登录页和设置页都放切换入口（未登录用户也要能读懂界面）。
- 云端错误：`loginFlow.ts` 的 `BY_CODE` 与 `labels.ts` 的枚举标签都改为键，由 `t()` 取字；未知 `code` 走通用文案，不直接显示云端的 `error` 字符串。
- 时间与数字：时间继续按手机本地时区（`formatLocalTime`），格式按当前语言；数字小数点沿用现状，不做本地化千分位（避免误读读数），列入 Open Questions 由人确认。
- 一致性检查：新增 Node 脚本，校验三种语言的键集合一致、占位符一致，并入 `npm run check`。
- 备选：引入 i18n 库。放弃：项目约定无第三方 UI／状态库，且词表规模小。备选：运行时翻译服务。放弃：行业术语要稳定，且需联网。
- Donut 的"多语言适配"章节可能自带方案或有约束（如系统语言接口）。**以文档为准，核实后若与本决策冲突，先回到设计再改**。

### D4 国外网络韧性：不新增协议，只补客户端行为

- 请求：显式超时，失败与超时都区分为"网络问题"，不显示成"没有数据"。
- 数据新鲜度：每个依赖实时数据的视图记录"最后成功更新时间"；读取失败时保留上次数据并明确标注"数据可能已过期"及时间，不清空。遵循既有约束：`telemetry/latest` 的 404 是"从未上报"，不是失败。
- 实时报警连接：保留指数退避；补两个触发点——App 回到前台、系统网络从断开恢复到可用时，重置退避并立即重连，同时刷新当前页数据。云端无心跳，客户端沿用现有"自行发现断开"的做法。
- 数据隔离：退出、切换账号、设备切换时，丢弃旧数据、关闭旧连接、取消在途请求（延续 `stationDevice.ts` 的跟随决策，不重复实现）。
- 线上地址：改为 HTTPS／WSS 域名。域名值由人提供，不在设计里猜；`DEBUG_MODE` 的本地改动不触碰。

### D5 包名、签名与分发

- 包名**不得**使用 `com.sansen.yeweiyi`（设备端 App 的包名，见 CLAUDE.md）。具体包名由人确认，列入 Open Questions。
- 签名 keystore 与口令不入库、不贴进 issue；后续版本必须用同一证书才能覆盖升级。keystore 的保管方式由人决定。
- 直接分发 APK。Android 内部分发的官方文档缺失，不假定有官方通道；安装说明写"允许安装未知来源应用"的步骤，覆盖更新靠同包名＋同签名＋更高版本号。
- 构建额度：每周 50 次原生构建，仅小程序改动的构建不占额度；排障时优先复用"仅小程序"打包。

### D6 验证方式

没有测试运行器，也未在 DevTools／真机运行过。验收分四层并分别记录：代码完成（`typecheck`、`check`）、构建成功、安装成功、真机联调与业务验收。"没装微信的真机"和"国外网络下的真机"两项必须单独出结果，不能用模拟器预览代替。

## Risks / Trade-offs

- **云端账号模型改动是阻塞项** → 先开云端 issue 并跟踪；客户端不自行发明接口；契约落地前用现有账号验证其余链路。
- **Donut 在没装微信的手机上不可用／受限** → 第一个里程碑就在未装微信的真机上验证；若失败，记录证据后回到本设计，不自动切换框架。
- **水印去不掉** → 已接受；写进已知限制。
- **共用代码影响原小程序**（词表、网络韧性） → 回归原小程序关键路径；平台分叉只限登录入口。
- **文案量大且西语未校对** → 词表集中、键一致性检查防遗漏；西语术语上线后改。英文／西语较长文字可能挤坏布局，列出需人眼检查的页面（登录、首页罐卡片、设备详情标签、记录筛选栏）。
- **国外网络不稳** → 以"让用户看得出数据新旧"为底线，而不是承诺不掉线。
- **明文 HTTP／IP 线上地址在 Android 上可能被拒** → 改 HTTPS 域名；域名未到位前该项阻塞真机联调。
- **keystore 丢失导致无法覆盖升级** → 备份由人负责，交付说明里写明。

## Migration Plan

1. 先在不改业务代码的前提下接入 Donut，产出第一个可安装包，验证"没装微信的手机能否运行"和平台资格；任一未知项出结果就写回 issue。
2. 云端 issue 与客户端并行：客户端先完成词表、网络韧性、登录页平台分叉；云端契约落地后接入用户名登录与改密。
3. 逐里程碑发布 APK；每个包记录版本、测试设备、账号角色、已验证／未验证项。
4. 回滚：原小程序的发布流程不变；App 只是新增交付物，出问题就不分发该 APK。
