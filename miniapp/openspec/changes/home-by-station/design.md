## Context

- 现状：`pages/devices` 是设备列表（`GET /api/devices`），点设备进 `device-detail`，实时数据是详情页的一个标签。`device-detail` 已有完整的遥测加载逻辑（含 404 = 从未上报）。
- 设计稿：28 个画板，首页为油站下拉 + 罐卡片列表，没有设备详情页。设计稿已导出 PNG，路径在仓库外，未入库。
- 云端（对照 yeweiyi-cloud main `957e11a`）：只有 `customers` 与设备，没有油站实体；`GET /api/devices` 返回 `{rows:[{device_name,is_online,last_online_at,last_offline_at,updated_at}]}`；遥测快照的 `Tank` 没有罐形状字段（只有 `oilType` 等）；没有批量遥测接口，一台设备一次请求。
- 业务关系（用户确认）：层级为 客户 → 油站 → 设备。一个客户有多个油站，首页下拉用于在这些油站间切换；一个油站有多台设备，一台设备同一时间至多属于一个油站；用户只能看到自己绑定的设备，他的油站列表由这些设备推导；设备配置类功能只有"油站管理员"能用。
- 与 ThingsBoard 的关系（2026-10-07 确认）：TB 侧不改。设备上报只带设备名，`device_name` 是唯一连接点，油站关系只存在云端业务库（与现在 customer 一致）。设备端、模拟器、已上线设备都不用动。
- 角色（云端现状）：JWT 的 `role` 只有 `platform_admin / customer_admin / customer_user`，没有油站级别的管理员。

## Goals / Non-Goals

**Goals:**
- 首页打开即见当前油站下所有罐的实时数据，与设计稿信息结构一致。
- 油站切换可用，且云端未上线油站时首页仍然可用（降级）。
- 不改变现有 `device-detail` 的行为与云端契约用法。

**Non-Goals:**
- 不在本仓库定义油站接口的最终契约；不做邀请、员工管理、油站管理的真实功能。
- 不做设置类页面的后端接入，不做交班/库存记录。
- 不重做 `device-detail` 的视觉；不引入状态管理库或 UI 组件库。

## Decisions

1. **油站来自云端新增实体，而不是客户端分组或"油站 = 客户"。**
   油站有名称、地址，归属于客户，设备关联到油站。备选：把 customer 当油站（一个客户有多个油站这一事实使其不成立）；客户端本地分组（换机/换账号丢失、无法共享）。均已否决。

2. **接口形状（2026-10-07 与产品确认，已写入 yeweiyi-cloud#43 的评论；契约以云端为准，此处只记客户端依赖了什么）：**
   `GET /api/devices` 每行新增可空的 `station_id`（信封仍是 `{rows}`）；新增 `GET /api/stations` → `{rows:[{id,name,address}]}`，范围与设备列表一致，只含当前用户已绑定设备所属的油站。管理接口（创建/改名/删除油站、给设备分配油站）供运维控制台使用，小程序不调用。本提案不在 `api.d.ts` 中先行添加这些类型；云端接口合入后，按"对照云端 main 核对 `api.d.ts`"的任务补类型。

3. **降级策略：** 没有油站数据时不出下拉，所有设备平铺。判断依据是"设备行里没有油站标识"，而不是版本号嗅探。部分设备缺油站标识时归入末尾的"未分组"。

4. **首页的数据加载：** 先读设备列表，再对当前油站下每台设备并行请求遥测快照；每台设备独立成功/失败，互不阻塞。受限于云端没有批量接口，设备很多时请求数等于设备数，先接受，见风险。

5. **选中油站的本机记忆：** 用 `wx.storage`，键名带账号用户名，避免换号后恢复到别人的油站。读写都要 try/catch，读不到就回退到列表第一项。

6. **罐图：** 罐形状来自设备配置：设备端 zhongchengyeweiyi 的 `OilCanSet.gunType`（0 = 卧罐，1 = 立罐，即"储罐设置"里的储罐类型），设备自己的首页就是按它切换罐图。但云端协议目前没有这个字段（遥测快照的 `Tank` 里没有；云端 `calibration.go` 也明确说形状不进入协议）。所以需要设备端把它作为每罐客户端属性发布（与 `probeType`、`capacityL` 同类），云端再透出。在此之前一律用卧罐图（已有素材 `tank-horizontal.png`），不用油品或罐号猜。设备端的类型只有卧罐/立罐两种，"长方体"只出现在罐表设置里，不影响首页罐图。

7. **复用而不是重写：** 把 `device-detail` 里"遥测快照 → 罐视图模型"的转换抽到 `utils/`，首页和详情页共用，避免两处各算一遍标签和 404 处理。

8. **页面职责：** `pages/devices` 改为首页（保持 tabBar 路径不变，避免动 `app.json` 的 tabBar）；新增 `pages/station-select`；`pages/org` 保留为"+"菜单的占位入口，本次不改行为，只改入口文案。

9. **油站可见范围 = 我绑定的设备所属的油站。** 用户只能看到自己绑定的设备，因此首页下拉只列出这些设备所属的油站；某油站下用户没有绑定的设备不显示，也不在卡片里提示"还有 N 台设备"，避免泄露设备存在性（与云端"未绑定与不存在同一 403"的设计一致）。

10. **设备配置类入口按"油站管理员"控制，但这是新的权限概念。** 云端目前没有该角色。客户端的角色判断只能用于显示/隐藏入口（真实校验在云端），所以：
    - 在云端提供油站管理员角色之前，设置类页面保持现状（本来就未接后端，只展示提示），不新增客户端的角色猜测。
    - 云端提供后，由其接口或 JWT claim 告知"当前用户是否为某油站的管理员"，客户端据此显示设置入口；不得用 `customer_admin` 冒充油站管理员。

11. **用户的油站由已绑定设备推导，不新增用户到油站的授权。** 保持现在的扫码绑定。代价：用户看不到同一油站里自己没绑定的设备，也无法"管理一个油站"。这是有意的取舍，按油站授权若将来需要，是云端另一项变更。

12. **设备换油站后，历史记录跟着设备走。** 报警与出入库记录不单独标油站，按设备当前所属油站过滤。对客户端无影响：首页只用设备列表里的 `station_id` 分组，不按油站去查记录。

13. **谁来维护油站：平台管理员（任何客户）与客户管理员（本客户），都在运维控制台里做，小程序内不做。** 对应 yeweiyi-admin#6。这与"油站管理员"（#44，设备配置类权限）是两件事，互不依赖。

## Risks / Trade-offs

- [云端油站实体迟迟不上线] → 降级路径保证首页可用；提案与代码都不依赖油站字段才能工作。
- [一台设备一次遥测请求，设备多时慢、耗流量] → 并行请求并按设备独立渲染；若实测慢，向云端提批量接口，不在客户端做缓存猜测。
- [油站管理员角色云端尚不存在] → 设置类入口的权限控制依赖云端新增；之前不做客户端角色推断，避免出现"看似受控实则可见"的假象。
- [设计稿没有设备详情页，用户点卡片进入的页面视觉与首页不一致] → 已在 proposal 标注设计缺口，不在本次处理。
- [首页展示的是快照不是实时流] → 页面显示上报时间并支持下拉刷新，避免用户把旧数据当实时。

## Migration Plan

1. 先落地降级版（无油站下拉，设备平铺 + 罐卡片），与云端无依赖，可独立验证。
2. 云端油站接口合入后，对照云端 main 核对并补 `api.d.ts`，再启用下拉与油站选择页。
3. 回滚：恢复 `pages/devices` 为设备列表即可，`device-detail` 未改动行为。
