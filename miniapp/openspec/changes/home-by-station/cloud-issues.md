## 草稿 A — yeweiyi-cloud：新增油站实体与设备关联

**标题：** 新增油站（station）实体，并在设备列表中返回设备所属油站

**背景**
小程序设计稿的首页是「油站 ▾」下拉 + 该油站下的罐卡片（见 `docs/miniprogram-design-gaps.md` §9）。业务上一个客户有多个油站，一个油站有多台设备。当前只有 `customers` 与挂在其下的设备，没有油站这一层。

**需要的能力**
- 油站实体：名称、地址、归属客户。同一客户下名称唯一。
- 设备到油站：一个设备至多属于一个油站；一个油站有多台设备。允许设备暂无油站（客户端会归入"未分组"）。
- `GET /api/devices` 每行返回所属油站标识；另有只读接口返回"当前用户已绑定设备所属的油站"列表（标识、名称、地址）。
- **可见范围：** 用户只能看到自己绑定的设备，油站列表只含这些设备所属的油站；不得暴露用户看不到的油站或设备数量。与现有"未绑定与不存在同一 403"的做法一致。
- 后台创建/维护油站与设备关联（platform_admin 与 customer_admin）；本阶段不做小程序内的邀请、注册、员工管理，账号只在后台创建。

**待你们决定**
1. 设备到油站是否一对多（一个设备只在一个油站）？
2. 油站与客户的关系是否一对多？
3. 现有设备迁移：默认无油站，还是按客户建一个默认油站？
4. `GET /api/devices` 保持 `{rows}` 信封，仅新增字段，是否可接受？（客户端会兼容缺字段）

**客户端的降级行为（已写入小程序 spec）**
设备行没有油站标识时，不显示下拉，所有设备平铺展示，因此云端分步上线不会影响小程序。

## 草稿 B — yeweiyi-cloud：油站管理员权限

**标题：** 新增"油站管理员"权限，用于控制设备配置类操作

**背景**
设计稿的设置类功能（参数修正、储罐设置、罐表设置、记录设置、报表设置、补录记录）只允许油站管理员使用。当前 JWT 的 `role` 只有 `platform_admin / customer_admin / customer_user`，没有油站级别的管理员。小程序不会用 `customer_admin` 冒充，否则会出现"看似受控实则可见"。

**需要的能力**
- 用户与油站之间的管理员关系（形态待定：新增油站级角色，或在用户-油站关联上加管理员标记）。
- 客户端得知"当前用户是否为某油站管理员"的方式（JWT claim 或接口字段）。注意 `apiClaims` 现有注释：角色变化要到下次登录才生效，若放在 JWT 里需要明确这一点。
- 服务端校验：配置类控制命令（`config.setTank`、`config.setProbe`、`config.setAlarmThresholds`）按油站管理员授权；客户端的显示/隐藏只是便利，不是安全边界。

**待你们决定**
1. 一个用户能否是多个油站的管理员？
2. 油站管理员能否配置自己没有绑定的设备？
3. 与现有 `customer_admin` 的关系：是否 customer_admin 自动是其客户下所有油站的管理员？
4. `config.*` 的参数结构仍未定义（`miniprogram-design-gaps.md` §1），这条依赖它。

## 草稿 C — zhongchengyeweiyi（设备端）+ yeweiyi-cloud：发布并透出罐形状

**标题：** 把每罐的储罐类型（卧罐/立罐）作为客户端属性发布，并由云端透出

**背景**
设备端 `OilCanSet.gunType` 保存储罐类型（0 = 卧罐，1 = 立罐），设备首页（`MinOilCanView`）据此切换罐图。小程序首页要对齐设计稿的卧罐/立罐两种罐图，需要这个信息。

云端现状：
- 遥测快照 `protocol.Tank` 没有该字段。
- `internal/protocol/calibration.go` 说明罐体形状（卧罐/立罐/长方体）不进协议，因为设备只持久化罐表曲线；这里要的是"储罐设置"里的储罐类型 `gunType`，是另一份数据，并且设备确实持久化了。
- 每罐客户端属性现有 `probeAddress`、`probeType`、`capacityL`，`gunType` 与它们同类。

**需要的能力**
- 设备端：把每罐 `gunType` 作为客户端属性发布（命名与枚举值待协议决定，建议字符串枚举而非 0/1，与现有 `probeType` 一致）。设备端注意：客户端属性只在 MQTT 重连时重新发布，改了储罐类型要主动重发。
- 云端：在 `protocol/attributes.go` 声明该属性，并在 `telemetry/latest` 的 `tanks[]` 中透出，或提供另一个只读接口；保持"未发布 = 缺省"，不要用 0 填充，客户端把缺省当作未知并使用卧罐图。

**待你们决定**
1. 属性名与枚举值。
2. 透出位置：并入 `telemetry/latest`，还是单独的设备配置只读接口（后者对"设备配置"类需求更通用，可与 `config.setTank` 的读回一起设计）。
3. 设备端旧版本没有该属性时的行为（客户端已按缺省处理）。
