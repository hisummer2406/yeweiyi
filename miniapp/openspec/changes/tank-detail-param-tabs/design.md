# 设计

核查基线：分支 `fix/42-device-reject-result`（7dcc073，含 #42）。

## 编辑组件 `param-editor`
属性：`kind`（calibration | tank）、`device`、`tank`、`station`（设备行的 station_id，-1 = 无油站）、`active`（首次激活才读取）、`readOnly`。

- 基准：读取该设备 tank-settings 镜像，取本罐那一行；`mirrorToForm` 得到各字段的「设备最近上报值」（缺失 = 未上报，不补 0），并显示镜像 `reportedAt`（不是页面打开时间）。
- 表单值 = 基准值叠加用户修改（edits）。只把与基准不同的字段记为修改并标「原值 → 新值」。
- 草稿只保存 edits 和当时的基准（`utils/paramDraft.ts`，纯函数、Node 检查），key = `param-draft:<kind>:<账号>:<设备>#<罐号>`，读回时校验账号、设备、罐号一致。没有修改即删除草稿。登出不清（key 含账号，与原储罐草稿规则一致）。
- 恢复：存在草稿时自动叠加并显示提示条（含保存时间）与「放弃草稿」。镜像刷新时未修改字段跟随新镜像；已修改字段保留输入，若其基准已变化则标注「设备上报值已变化，请复核」；新镜像已等于输入值的修改自动消除。
- 下发：`buildArgs` 只发合法且与镜像不同的字段；下发原因必填；确认弹窗列设备、罐号、各字段前后值与单位、原因。`confirmAndSend` 增加 `stay` 选项：受理后返回命令而不跳转；结果未确认的找回、同编号重试、模块锁等规则不变。
- 结果：组件内按云端 `terminal` 轮询命令（2s），终态后：成功 → 按 `echoState` 核对新鲜回显（5s，3 分钟上限）；拒绝/失败 → 显示 #42 的设备原因；过期 → 结果无法确认。结果绑定设备+罐+命令号，切罐/换机后不显示到别的罐；页面隐藏、组件卸载停止轮询。保留「查看操作记录」入口。

## 罐详情
- `TABS` = snapshot / calibration / settings；两个编辑页签只在设备有效且已选中可见罐时显示组件，否则提示先选罐。
- 页签用 `hidden` 切换，组件常驻，切页签不丢输入。
- 页内不提供罐切换（用户 2026-11-14 决定）：首页点哪个罐就显示哪个罐；要看别的罐回首页点。设置页入口的罐号选择仍在，切罐时若有未下发修改，弹出：保留草稿并切换 / 放弃修改并切换 / 取消。
- 设备的 station_id 取自 `GET /api/devices` 行；未知时组件不允许下发（`commandGuard` 仍在发送前复核）。

## 旧入口
`calibration`、`tank-config` 改为同一薄页面逻辑（`utils/paramPage.ts`）：首页当前油站 → 唯一设备 → 罐；支持 `?tank=`；多罐且未指定时不默认第一个，提示选择罐号。
